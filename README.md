# JByteVM

Крайне компактная встраиваемая JVM, в первую очередь для написания модов, но без ограничения только моддингом.

Название выбрано пользователем 10 ноября 2026 года. Проект создан из беседы «Логика» в Tethium.

## Требования пользователя

- Только интерпретатор, без JIT. Скорость интерпретации — один из главных приоритетов.
- Ориентир совместимости — Java 25. Нужен только необходимый набор стандартных классов; его состав обсуждаем отдельно.
- FFM: вызовы Java → native и native → Java, включая вложенные цепочки native → Java → native → … .
- Образ для Windows должен быть меньше **256 КБ**.
- Для ещё более урезанного набора классов желательная цель — **32 КБ**.

Цифры размера — требования и цели, а не уже подтверждённые результаты. Пока нет реализации или замеров.

## Что нужно решить перед реализацией

1. **Бюджет размера.** Что входит в образ: исполняемый файл / DLL, классы, служебные данные и зависимости; как считаем размер при поставке и после распаковки.
2. **Минимальная библиотека.** Какие классы нужны модам в первом рабочем профиле. Начать обсуждение с Object, String, массивов, исключений и минимального native API; остальное согласовать по сценариям использования.
3. **Границы совместимости.** Поддержка class-файлов Java 25, набор инструкций и механизмов JVM, загрузка классов, отражение, потоки и инициализация классов. Не подменять поддержку формата полной совместимостью со всей платформой Java.
4. **Native-интерфейс.** Нужный объём FFM API, соглашения о вызовах, память, callbacks/upcalls, повторный вход в VM и вызовы с native-потоков.
5. **Архитектура.** Язык реализации, устройство интерпретатора, представление объектов и сборка мусора. Выбирать по размеру и измеряемой скорости, не фиксировать заранее без сравнения.

## Первый рабочий срез — предложение

Загрузить небольшой class-файл, скомпилированный Java 25, выполнить вычисление в интерпретаторе и показать двусторонний native-вызов с повторным входом в Java. Для этого среза сразу измерить полный размер Windows-образа и время выполнения.

Состав библиотеки и точные ограничения первого среза сначала обсуждаем с пользователем.

## Продолжение
